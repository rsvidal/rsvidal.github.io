🏥 bd-healthcare-platform

BD Healthcare Platform | BDWiderlab · BDSupport · BDForms — modular monolith rebuilding BD's hospital software on .NET 9, since 2025

.NET 9 C# 12 EF Core 9 Minimal APIs Swagger/OpenAPI MediatR FluentValidation Serilog Polly QuestPDF Next.js 15 React 19 TypeScript Tailwind Uno Platform SQL Server Oracle DB2 MySQL SQLite xUnit Moq Vitest Playwright Azure DevOps

→ Three products on one shared framework: medical backend for lab requests (BDWiderlab), support & equipment inventory (BDSupport), and digital lab request forms with PDF417 barcodes replacing OMR paper forms (BDForms)

→ Patient safety by design: globally unique sample numbers even on offline stations (append-only range ledger), positive patient identification, ISO 14971 risk analysis

→ HIS/LIS integration through isolated read-only services (BDPatient, BDLis) with typed SDKs: patient data kept separate, the product degrades gracefully if a hospital system is down

→ Tamper-evident audit trail: every audit record HMAC-signed with a key kept outside the database (GDPR art. 32, ENS, ISO 27001)

→ Clean Architecture + DDD, CQRS with MediatR, Specifications, Outbox pattern, optimistic concurrency; REST endpoints as Minimal APIs documented with Swagger/OpenAPI

→ Security: JWT with refresh tokens + MFA (TOTP), RBAC with row-level authorization and token revocation, AES-GCM column encryption, signed audit trail

→ Five database providers from one codebase (SQLite, SQL Server, MySQL, Oracle, DB2), with per-provider EF Core migrations

→ Web: Next.js 15 / React 19 / TypeScript with a shared component library; BDForms on Uno Platform (WinUI 3, WebAssembly, Android) with TWAIN scanning and QuestPDF printing

→ ~11,500 unit/integration tests (xUnit, Moq) + Vitest frontend tests + Playwright E2E; 83 ADRs; Azure DevOps CI/CD

→ Built with an AI-assisted workflow (Claude Code agent teams guided by project rules and ADRs)
